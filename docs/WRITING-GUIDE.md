# Writing guide

Write for the reader. Lead with the information they need, use familiar words and concrete verbs, and explain why when it helps a decision.

## Instructions

- Put prerequisites and important restrictions before the action they govern.
- Use numbered steps for a sequence and bullets for independent points.
- Include the working directory for commands when it matters.
- Describe expected results and recovery when they are useful.
- Link to the primary reference rather than duplicating long procedures.

## Precision

- Use **must** for requirements, **must not** for prohibitions, **may** for permission, and **should** for recommendations.
- Keep conditions, actors, permissions, and safeguards intact when rewriting.
- Distinguish supported behavior from test coverage and limitations.
- Use consistent technical terms and define project-specific terms where readers need them.
- Preserve commands, paths, API fields, error contracts, fixture data, and legal text.

## Review

Check instructions and claims against the implementation. Run relevant tests and check links. Read the result for clarity, flow, and unnecessary repetition.

Prompts and tool descriptions can affect agent behavior; review them as instructions, not just prose.
