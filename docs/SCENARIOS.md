# Native workflow scenarios

These are required observations, not claims of real-model qualification.
The machine-readable catalog is `packages/prometheus/qualification/scenarios.mjs`.

| Scenario | Required observation | Automated checks |
| --- | --- | --- |
| Native goal ownership | Exactly one native `/goal`; no Prometheus replacement or invocation. | Plugin and installed-package tests. |
| Command admission | Attachments, delivery, agent, model, tools, and permissions remain native. | Plugin tests and scripted native commands. |
| Plan restrictions | No product writes or Build-child bypass from preparation. | Plugin, verification, and native-denial tests. |
| Linux execution | Native shell performs an authorized local experiment. | Scripted native tests; no macOS skip. |
| Native continuation | Native reviewer requests continued work after preparation. | Scripted native-goal test. |
| Independent verification | Fresh evaluator cites its own native tool results. | Verification and scripted native tests. |
| Failed check | Report fails or remains unresolved. Origin repairs; no plugin repair loop. | Verification tests. |
| Changed files | Candidate differences prevent acceptance or invalidate current accepted status. | Artifact and verification tests. |
| Cancellation | Pending verification stops; late reports cannot pass. | Verification tests and native cancellation checks. |
| Reload | Records survive. Old pending work cannot resume or report acceptance. | Verification tests. |
| Legacy data | Old database bytes remain unchanged; obsolete campaigns cannot start work. | Migration tests. |

## Live model checks

Use an explicitly approved model and allowance for these checks:

1. Alternate spikes and user questions. Confirm that findings and decisions remain distinct.
2. Run a Plan investigation that needs a write experiment. Confirm that it requests Build instead of bypassing restrictions.
3. Give native `/goal` an agreed objective. Confirm ordinary repair without repeated routine instructions.
4. Request independent verification of a defective candidate. Confirm that relevant evidence causes rejection.
5. Repair the candidate in the origin. Request a fresh evaluation and check the exact delivered files.
6. Deny a required check. Confirm an unresolved result, not acceptance or a permission bypass.
7. Interrupt pending work and reload the plugin. Confirm that no work restarts without a new request.

Scripted provider responses cannot establish these reasoning properties.
